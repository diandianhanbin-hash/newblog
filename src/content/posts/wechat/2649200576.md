## 总述

本次大会传递出的核心趋势可以概括为：

> AI的发展正在从“模型能力竞争”进入“企业智能体建设阶段”。企业真正需要的不是一个会回答问题的AI，而是一个能够理解企业上下文、主动发现问题、执行任务、持续进化并解决问题的智能协作者。

未来企业AI竞争的核心，不只是模型，而是：

```
企业知识
+
Agent Runtime
+
Skill体系
+
Eval体系
+
持续反馈闭环
```

而人的价值也会发生变化：

从：

> 执行任务的人

转变为：

> 定义目标、判断结果、做关键决策。

## 一、AI发展的整体趋势

### 1.1 模型能力逐渐成熟，竞争重点转向Agent化应用

过去几年，AI发展的核心竞争集中在：

- 模型参数规模；
- 推理能力；
- 多模态能力；
- 代码生成能力。

随着基础模型能力逐步提升，行业关注点正在发生变化：

> 从“模型能不能回答问题”，转向“模型能不能完成复杂任务”。

因此未来竞争重点逐渐转向：

- Agent能力；
- 长任务执行能力；
- 企业业务理解能力；
- 可靠性和可控性。

大会多个议题均体现这一趋势：

- Agent Runtime；
- Agent Swarm；
- Human in the Loop；
- 长流程任务执行；
- 企业语义模型。

* * *

## 二、企业AI落地的主要方向

目前企业探索Agent落地主要集中在两个方向。

* * *

### 2.1 研发智能化

目标：

提升软件研发效率，同时保证研发过程可控。

主要覆盖：

##### 需求阶段

- 需求理解；
- Spec生成；
- 风险识别；
- 需求澄清。

##### 开发阶段

- 任务拆解；
- 代码生成；
- 自动调试；
- 自动执行。

##### 测试阶段

- 自动生成测试场景；
- 自动验证。

##### 运维阶段

- 异常分析；
- 根因定位；
- 自动修复建议。

### 2.2 企业知识与数据资产智能化

企业真正落地Agent最大的基础不是模型，而是：

> 企业知识如何被AI理解。

因此大量企业开始建设：

- 企业知识库；
- 业务语义模型；
- 数据资产体系；
- 问题经验库。

* * *

## 三、Agent发展的核心变化：从回答问题到主动发现问题

这是本次大会多个议题共同体现的重要趋势。

* * *

### 3.1 当前AI主要解决“回答问题”

传统AI交互模式：

```
人提出问题
↓
AI回答
↓
任务结束
```

例如：

- 查询资料；
- 编写代码；
- 总结文档。

这种模式的问题：

AI只能处理：

> 人已经明确表达出来的问题。

但是企业中的大量问题：

并没有被明确提出。

* * *

### 3.2 企业真正需要的是“发现问题”

企业真实工作流程：

```
目标提出
↓
信息收集
↓
发现未知信息
↓
澄清问题
↓
形成判断
↓
执行方案
```

其中最困难的是：

> 找到正确的问题。

因此大会多个企业都强调：

Agent需要具备主动提问能力。

* * *

### 3.3 Agent主动提问的典型模式

例如需求分析：

传统方式：

业务：

> 我要开发一个支付功能。

研发：

> 请补充需求。

* * *

Agent模式：

Agent主动追问：

```
目标用户是谁？

交易失败怎么办？

是否需要幂等？

是否存在状态变化？

涉及哪些外部系统？

历史是否发生过类似问题？
```

最终形成：

```
业务目标
+
完整上下文
+
明确约束
+
执行方案
```

* * *

### 3.4 这也是为什么企业强调Context

大会多个议题强调：

> Agent不是缺少数据，而是不理解数据之间的关系。

因此需要：

```
数据
↓
上下文
↓
业务语义
↓
判断能力
```

例如：

监控系统发现：

```
支付成功率下降
```

普通AI：

> 支付成功率下降。

Agent：

主动分析：

```
什么时候开始？

哪个渠道？

是否版本发布？

是否数据库异常？

影响哪些客户？
```

并主动收集证据。

* * *

### 3.5 Agent未来角色变化

未来Agent的发展可以分三个阶段：

阶段

模式

特点

第一阶段

回答型AI

人提问，AI回答

第二阶段

任务型Agent

人给目标，AI执行

第三阶段

顾问型Agent

人给目标，AI主动澄清和规划

企业真正期待的是第三阶段。

## 四、企业AI落地的共性架构

综合大会多个企业实践，可以总结出：

```
业务目标

Context / 企业知识准备
↓
问题理解与Spec生成
↓
任务拆解
↓
Agent执行
↓
Runtime治理
↓
质量验证
↓
人工决策
↓
反馈闭环
```

## 五、企业AI核心基础设施

### 5.1 企业Context体系

这是Agent落地的第一基础。

包括：

- 企业知识；
- 业务流程；
- 系统关系；
- 历史案例；
- 专家经验。

关键不是存储信息，而是：

> 让AI理解企业世界。

* * *

### 5.2 Agent Runtime

负责：

- Agent生命周期管理；
- 权限控制；
- 工具调用；
- 执行监控；
- 审计追踪。

安全需要贯穿：

##### 事前

- 任务拆解；
- 权限校验；
- 风险判断。

##### 事中

- Agent行为监控；
- 工具调用限制；
- 异常阻断。

##### 事后

- 全链路审计；
- 问题追踪；
- 经验沉淀。

* * *

### 5.3 Skill体系

Skill本质：

> 将专家经验结构化。

包括：

- 方法论；
- 判断规则；
- 操作流程；
- 最佳实践。

例如：

测试专家Skill：

```
需求分析方法
↓
风险识别规则
↓
测试设计框架
↓
历史缺陷经验
```

* * *

### 5.4 Eval体系

企业不能只关注：

> Agent有没有完成任务。

还需要评估：

- 正确率；
- 稳定性；
- 幻觉率；
- 风险。

需要：

- Benchmark；
- Bad Case；
- 灰度；
- 回滚机制。

* * *

### 5.5 数据闭环体系

优秀Agent不是一次建设完成。

需要：

```
执行
↓
反馈
↓
发现问题
↓
优化Skill
↓
能力提升
```

* * *

## 六、知识库建设：行业共识，但仍缺少统一答案

大会几乎所有企业都认可：

> 企业AI落地首先需要知识资产建设。

但是对于：

- 知识如何建模；
- 知识颗粒度；
- 知识生命周期；

目前仍没有统一方案。

* * *

### 6.1 知识需要结构化

未来知识库不是：

```
大量文档
```

而是：

```
对象
+
关系
+
状态
+
经验
+
规则
```

类似企业知识图谱。

* * *

### 6.2 问题库成为重要资产

多个企业强调：

问题不能只记录：

```
问题：
支付失败
```

而应该记录：

```
问题现象
↓
产生原因
↓
分析过程
↓
解决方案
↓
适用范围
↓
避免方式
```

否则AI无法理解：

> 为什么这样解决。

* * *

## 七、当前行业仍面临的问题

虽然企业AI方向已经比较明确，但是仍存在几个挑战。

* * *

### 7.1 企业知识建模缺少统一方法

目前：

- 大家知道需要知识；
- 但是不知道最佳结构。

* * *

### 7.2 Agent可靠性仍需要验证体系

挑战：

- 幻觉；
- 错误判断；
- 长任务失控。

因此：

Eval、Runtime、安全成为关键。

* * *

### 7.3 企业落地依赖领域专家

Agent能力不是简单部署模型。

真正有效需要：

```
模型
+
领域知识
+
业务流程
+
专家经验
+
治理体系
```

* * *

## 八、对测试团队转型的启示

结合大会趋势，对测试团队有几个重要启发：

* * *

### 8.1 测试价值从发现问题转向定义问题

未来AI可以生成：

- 用例；
- 数据；
- 执行结果。

但是测试专家价值在于：

主动提出：

- 哪些风险需要关注？
- 哪些问题容易遗漏？
- 如何验证业务正确？

这与Agent主动提问能力高度一致。

* * *

### 8.2 测试资产需要升级为知识资产

未来测试资产不应该只是：

```
测试用例
```

而应该包含：

```
业务模型
+
风险模型
+
历史问题
+
判断规则
+
专家经验
```

* * *

### 8.3 测试人员需要向“质量Agent设计者”转型

未来测试团队的重要能力：

不是写更多测试。

而是：

> 把优秀测试专家的思维方式沉淀成Skill，让Agent具备质量判断能力。
