## 背景

k8s支持的配置主要有以下几种：

- Secret
- ConfigMap
- Downward API
- ServiceAccountToken

一般我们可能会用到的是前两个

## Secret

`Secret`比较典型的场景就是存放一些凭证，例如用户名密码这些。

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: test-projected-volume
spec:
  containers:
  - name: test-secret-volume
    image: busybox
    args:
    - sleep
    - "86400"
    volumeMounts:
    - name: mysql-cred
      mountPath: "/projected-volume"
      readOnly: true
  volumes:
    - name: mysql-cred
      secret:
        secretName: user
```

这里我们会使用`user`这个凭证。我们在创建之前，需要先创建这两个`secret`。

```bash
echo 'sven' > username.txt
kubectl create secret generic user --from-file=./username.txt 
secret/user created

kubectl get secrets
NAME                  TYPE                                  DATA   AGE
user                  Opaque                                1      57s
```

我们创建这个容器，然后进去查看

```bash
kubectl exec -it test-projected-volume -- /bin/bash
cd projected-volume/
ls
username.txt
cat username.txt 
sven
```

可以看到凭证已经被写入到挂载对应的目录下了。

这种方式，我们的数据将会保存在`k8s`的`etcd`中，一旦这个数据在`etcd`中被更新了，那么所有的`pod`内的这个文件都会被更细。

## ConfigMap

`ConfigMap`指的是那些不需要加密的信息，例如常规的配置文件。

举个例子，我们有这样一个配置文件

```bash
cat xxx.properties
color.good=purple 
color.bad=yellow 
allow.textmode=true 
how.nice.to.look=fairlyNice
```

我们使用这个配置文件创建一个`ConfigMap`

吧刚刚的`yaml`文件调整一下

```bash
apiVersion: v1
kind: Pod
metadata:
  name: test-configmap
spec:
  containers:
  - name: test-configmap
    image: busybox
    args:
    - sleep
    - "86400"
    volumeMounts:
    - name: mysql-cred
      mountPath: "/projected-volume"
      readOnly: true
  volumes:
    - name: mysql-cred
      configMap:
        name: xxxconfig
```

创建容器后可以看到，这个文件已经在目录中了。

```bash
/projected-volume # ls
xxx.properties
/projected-volume # cat xxx.properties 
color.good=purple 
color.bad=yellow 
allow.textmode=true 
how.nice.to.look=fairlyNice
```

- 一些注意点

首先`ConfigMap`不是用来存储大量数据的，它只能存储1MB的数据。

`ConfigMap`也是存储在`etcd`中，一旦发生了变更，那么所有的容器内的`ConfigMap`也会一并发生变更。

`ConfigMap`里面的对象应该是确定的，也就是不会因为容器创建而发生变化的数据。
